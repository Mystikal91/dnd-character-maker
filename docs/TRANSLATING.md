# Translating

All texts live in `locales/<language>/`. English (`en`) is the source language; every other
language is a translation of it. A missing translation falls back to English, so a language can
be translated little by little.

```
locales/
  en/ui.json              interface texts
  en/srd51/*.json         rules texts (names, descriptions) of the SRD 5.1 pack
  it/ui.json              Italian interface
  it/srd51/*.json         Italian rules texts (added as they are translated)
```

Every file is a flat JSON object. Interface keys look like `sheet.armorClass`; rules keys look
like `fireball.desc` (`<entry slug>.<field>`). Text may contain `{placeholders}`, which must be
kept exactly as written (a test checks this for the interface texts).

## Weblate setup

Use one Weblate project for the whole app, and add components with the **Add-on "Component
discovery"** so new files appear on their own:

| Setting | Value |
| --- | --- |
| Version control system | Git, repository `https://github.com/Mystikal91/dnd-character-maker.git`, branch `main` |
| File format | JSON file (`json`) |
| Regular expression to match translation files | `locales/(?P<language>[^/.]*)/(?P<component>.*)\.json` |
| Source language | English |
| Language code style | Default (`it`, `en`) |
| Monolingual | Yes: the template (source) file is `locales/en/<component>.json` |
| Push branch | A separate branch, e.g. `weblate`, merged by pull request |
| Edit base file | No: only the English files in the repository define the source texts |

Notes:

- `locales/en/srd51/*.json` is generated by `npm run data:srd51`; never translate or edit it by
  hand. Change the generator instead.
- Official translations of the rules (if their license allows distributing them) should be
  imported once and then **locked** in Weblate, so contributors only review and fix them.
- To add a language: create `locales/<code>/ui.json` (Weblate can do it), add the code to
  `LANGUAGES` in `src/app/language.logic.ts`, and import its interface file in
  `src/i18n/ui.ts`.

## Importing the official SRD translations

Wizards publishes the SRD 5.1 in Italian, French, German and Spanish under the same CC-BY-4.0
license ([download page](https://www.dndbeyond.com/srd)). `scripts/srd-translations/` imports
their texts into `locales/<language>/srd51/`:

```bash
pip install pymupdf
python scripts/srd-translations/import_spells.py it path/to/SRD_CC_v5.1_IT.pdf
```

The PDFs sort entries in the translated alphabetical order, so each spell is matched to its
English entry by level, school, components, ritual/concentration flags and the numbers and
dice in its text, using a global best assignment. The script prints the few matches it is less
sure about (a school mislabelled in the PDF, for example); names there are still right.

Other importers read the PDFs by structure instead: body text is Cambria and headings are
Calibri, whose size gives the heading level in all four documents (`pdf_sections.py`). Small
lists are found by their shape (`reference.py`) and paired with English ids through a glossary
of translated headings (`import_reference.py`).

```bash
python scripts/srd-translations/import_reference.py it path/to/SRD_CC_v5.1_IT.pdf
```

```bash
python scripts/srd-translations/import_species.py it path/to/SRD_CC_v5.1_IT.pdf
python scripts/srd-translations/import_classes.py it path/to/SRD_CC_v5.1_IT.pdf
python scripts/srd-translations/import_tables.py it path/to/SRD_CC_v5.1_IT.pdf
```

The options a class offers and the weapon properties come next. Run these after the importers
above, in this order, because they add to the files instead of replacing them:

```bash
python scripts/srd-translations/import_options.py it path/to/SRD_CC_v5.1_IT.pdf
python scripts/srd-translations/import_variants.py it path/to/SRD_CC_v5.1_IT.pdf
python scripts/srd-translations/import_properties.py it path/to/SRD_CC_v5.1_IT.pdf
python scripts/srd-translations/import_misc.py it
```

`import_options.py` pairs eldritch invocations, metamagic, fighting styles and pact boons with
the PDF sections under their parent feature, using the numbers, the translated spell, skill and
ability names a text mentions, and its length; pairs that were checked by hand and corrected
are in `OVERRIDES`. `import_variants.py` gives the numbered variants ("Action Surge (2 uses)")
the title of their section plus a translated suffix.

The monsters are read from the stat blocks of the same PDFs (`locales/<language>/srd51/monsters.json`),
after `npm run data:srd51` has written the English ones:

```bash
python scripts/srd-translations/import_monsters.py it path/to/SRD_CC_v5.1_IT.pdf
python scripts/srd-translations/import_monsters.py it path/to/SRD_CC_v5.1_IT.pdf --show goblin
```

`--show` prints what was read for one monster. The labels of a stat block differ per language, so
a block is paired with its English monster by armor class, hit points, XP and the six ability
scores (with fallbacks where the database and the book disagree). The translations sort the
traits and actions alphabetically, so inside a block they are paired by their numbers and by the
game words they use (abilities, skills, conditions and damage types, translated through the files
imported above), and an entry that two others could replace almost as well stays English. The SRD
prints one block where the database has several (the forms of a werewolf, the swarms of insects):
those share the block's texts and keep their own names.

Imported so far, in Italian, French, German and Spanish: spells, abilities, skills, conditions,
alignments (names and descriptions), species, subspecies, the traits that belong to one species,
the background with its personality tables, the twelve classes with their starting equipment and
spellcasting text, the subclasses, about 90% of the class features (366 of 407), the languages,
about 91% of the monster texts (the missing ones are the descriptions, which the PDFs do not have,
and a few entries that could not be paired with certainty), and 40-45% of the item names (all armor, nearly all weapons, and the gear whose cost and weight
are unique). Tables are read by baseline from the Calibri 9 cells (`pdf_tables.py`); armor is
paired by position and everything else by cost, weight and damage dice, keeping only unique
matches. An item or feature stays in English when it cannot be paired with certainty. School
names are missing in German. The weapon properties are complete.

Known gaps in the source PDFs: the Italian SRD has no text for the conditions frightened, prone,
restrained and stunned (only their names are added, by hand, in `import_misc.py`), and exhaustion keeps its English text everywhere because its table is
not part of the running text. Item descriptions, proficiencies and the remaining gear are not
imported yet.

## Automatic translation of what is missing

Texts that have no translation yet (about 13% of the rules texts, and everything imported from
Aurora files, which is English) can be translated by [DeepL](https://www.deepl.com/pro-api) as
they are read. It is off by default and each person uses their own DeepL key, free or paid, in
*Automatic translation* (footer). Requests go through the relay in `workers/translate-proxy/`
(see [TRANSLATION_PROXY.md](TRANSLATION_PROXY.md)), because DeepL does not accept calls from web
pages.

- only the text on screen is sent, once: translations are kept in IndexedDB by language and
  English text, so nothing is translated twice, and a text translated by an official or a
  Weblate translation is never sent;
- a machine translation is marked, with a button to read the English original;
- distances are converted to metric before the text is sent, when the units are metric;
- text written by the person (homebrew) is never sent.

## Checking a translation locally

```bash
npm test
```

The language tests fail when a translated interface file has a key English does not have, or
changes the `{placeholders}` of a text.
